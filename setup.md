# Setup interview

Run this when `CLAUDE.md` still starts with the "Not set up yet" line. Goal: every `<placeholder>` in `CLAUDE.md` replaced with the owner's own facts, in their words, and the repo moved to a private remote of theirs.

**Save as you go.** A session can end mid-interview (a crash, a compaction, the owner walking off), and nothing said may be lost. Each step below (the steps before the questions, every question, every optional section) ends the same way, before the next one starts: write what you learned where it belongs ("Where answers go"), set `next:` in the "Not set up yet" line to the following step, commit by explicit path and push (locally only until the private remote is set). A session that finds that line starts at the step it names.

## Before the questions
1. Say what is coming in two lines: about 15 minutes of questions, one at a time; any can be skipped and filled in later.
2. Memory hooks: in this repo's root, `git clone https://github.com/zucchini-chat/one-fact-one-place` (git-ignored: a clone, not part of this repo), then `git config core.hooksPath one-fact-one-place/hooks`. From then on, an agent's commit that may repeat a fact already in the repo or links to nothing stops until the agent fixes it or gives a reason; the owner's own commits only show the list. The clone also holds the storage rules `CLAUDE.md` loads; the repo cleaner updates it. On by default: it is cheap. Tell the owner it is on; off: `git config --unset core.hooksPath`. Check: `python3 tools/overview.py` prints no `Memory hooks` line. The same hooks run the `.tyaml` type check, which needs PyYAML (MIT) in the first `python3` on PATH: if `python3 -c 'import yaml'` fails, ask the owner, then `python3 -m pip install --user pyyaml`; if pip refuses because that Python is externally managed (Homebrew's Python does this), use a Python from a version manager such as asdf instead of forcing pip.
3. Private remote. This clone still points at the public scaffold, and everything the owner says will land in commits. Ask for an empty **private** repo of theirs (GitHub, GitLab, any git host), then, before switching, write `git remote get-url origin` and `git rev-parse HEAD` into `agents/repo-cleaner.md` > "Scaffold updates" (Source and Last ported), and run `git remote set-url origin <url> && git push -u origin master`. Until they have one, commit locally and skip the push.

## The questions
One at a time, in this order. A short follow-up when an answer is vague; never ask what a later question or a search will answer anyway.
1. Name, how to address them ("you", a name), pronouns, and the language of replies.
2. Goals, in priority order: what they want in the next year or two, most important first. Push for 3-5 concrete ones and for which wins when two conflict.
3. Roads: the paths they have already chosen toward those goals. Everything else is off-limits for nudges.
4. Who they are: age, work, where they live and since when, where before, who lives with them, what they do off the clock.
5. Home: address or neighbourhood. Look up the coordinates yourself and confirm them; that point is the "near me" centre.
6. Ordinary weekday: wake, work hours, meals, family time, the hard stop, days off. The stop time drives the "past <STOP_TIME> - stop" rule and the stop call.
7. Standing decisions: things already settled that agents must not re-propose.
8. Contacts: which email is for what (sign-ups and shops vs people), phone, messenger.
9. Calendar and mail: which ones they use, a work account's too. Nothing has to be plugged in now (`tools.md`).
10. Topic areas: the 3-6 parts of life they want help with (work, health, money, home, kids, travel, food...).
11. The machine: which one stays on, and whether Zucchini is installed on it.

## Where answers go
- Fill `CLAUDE.md` in place: keep its structure and rules, replace placeholders, set pronouns as they prefer. A skipped answer keeps its placeholder and is not asked again.
- One folder per topic: `<topic>/CLAUDE.md` with a title, one line on what it covers and a file table (`| File | Covers |`), plus a row in the topic table of `CLAUDE.md`. What they told you about that topic goes in there, not in the root file; a topic fact said before question 10 gets its folder right away.
- `people.md`: everyone they named.
- Times: set the morning brief and stop call times in `agents/chief-of-staff.md` and `agents/CLAUDE.md` from their ordinary day.
- Calendar: if a calendar command already works, write `tools/calendar-today` as `tools.md` > "Calendar" says and run `python3 tools/overview.py` to check it.

## Shared browser (optional)
One always-on Chrome with its own profile that every agent drives: [shared-chrome-mcp](https://github.com/zucchini-chat/shared-chrome-mcp). It is what lets agents do computer work on sites (forms, uploads, accounts). Rules: `tools.md` > "Browser". Needs Google Chrome and Node.js; if either is missing, ask before installing it. Offer the step; skip it if they decline.
1. Claude Code, from this repo: `claude plugin marketplace add zucchini-chat/shared-chrome-mcp --scope project && claude plugin install shared-chrome-mcp@shared-chrome-mcp --scope project`. Then set `"autoUpdate": true` on the `shared-chrome-mcp` entry under `extraKnownMarketplaces` in `.claude/settings.json`, so new versions arrive by themselves, and commit that file. Codex (it fetches the latest at every start): `codex mcp add browser -- npx -y github:zucchini-chat/shared-chrome-mcp`.
2. Keep Chrome running: on macOS `npx -y github:zucchini-chat/shared-chrome-mcp install` (a launchd agent); elsewhere run `npx -y github:zucchini-chat/shared-chrome-mcp start` from the init system. Check with `npx -y github:zucchini-chat/shared-chrome-mcp status`. The new tools show up at the next session start.
3. Ask the owner to log in, in that Chrome's window, to the sites they want agents to use (mail, calendar, shops, work tools; an employer's sign-in goes in that job's own Chrome instead: "A job" below). Say plainly that this only saves time: agents can log in by themselves later in this profile, and every login made there stays for all agents.

## A job (optional)
Everything in this repo is pushed, so an employer's document saved here leaves the employer's control on the first push. Offer the step: do they use this agent for a job or a contract, for whom, under an NDA? None, or they decline: skip it. Per job:
1. Copy the template next to this repo, never inside it: `mkdir ../<job> && cp -R job-template/. ../<job>/ && git -C ../<job> init && git -C ../<job> config core.hooksPath "$PWD/one-fact-one-place/hooks"` (the memory hooks of this repo's clone, which the repo cleaner keeps current). Fill its `CLAUDE.md` with the owner: their role, the employer's repos, tracker, calendar, which AI tools the employer approved and on which account (none yet: agents keep to the owner's own notes until it does). Delete its template line; commit after step 2. No remote; the employer's own remote only if the owner wants it and the employer allows it; never a personal one.
2. Work identity. It edits `~/.gitconfig`, outside this repo, so ask first: `git config --global 'includeIf.gitdir:<absolute path of the job folder>/.path' '~/.gitconfig-<job>'` and `git config -f ~/.gitconfig-<job> user.email <work email>`. A work code-host account: `gh auth login` for it, then `gh auth switch` back to the personal one, since a login makes the new account active for every session. Then check `git config user.email` in the job folder and commit there; if they declined the `includeIf`, with the identity they choose.
3. Chat: a new Zucchini chat in the job folder, titled `<JOB>` (the job's short name), started with "Read CLAUDE.md".
4. Browser, only if agents will work in the employer's web apps: a second shared-chrome-mcp with its own profile, label and a free port, `<port>` (the shared Chrome's is 9222; count up from there, one per job): `npx -y github:zucchini-chat/shared-chrome-mcp install --port <port> --profile ~/.shared-chrome-mcp/<job> --label shared-chrome-mcp-<job>` (elsewhere than macOS, `start` with the same flags; `status` with them checks it). Then in the job folder, for Claude Code only (Codex's `codex mcp add` is global and would reach every personal session, so a Codex session there does no web work in the employer's accounts): `claude mcp add --scope project <job>-browser -- npx -y github:zucchini-chat/shared-chrome-mcp --port <port> --profile ~/.shared-chrome-mcp/<job>`, and write the server name, port, profile and label into the job's `CLAUDE.md`. The owner signs in to the employer's accounts in that Chrome's window, never in the shared one.
5. Material already here: if this repo already holds the employer's material (in `work/` or anywhere), move it to the job repo. It stays in this repo's pushed history; cleaning that is a history rewrite, the owner's call. `work/` here keeps the owner's own side: career, job search, the terms of their own contract.
6. Code-host replies, only with the mail desk and its guard on (`agents/mail-desk.md`): first add `- <org> <JOB>` under `agents/mail-desk.md` > "Code-host routes"; desk already running: `SendMessage` `email watcher` to restart its "mail desk feed" watch and reread `agents/mail-desk.md`, and wait for its reply. Only then have GitHub mail the employer org's Participating and @mentions notifications to an inbox the desk watches (Settings > Notifications: Email on for Participating and @mentions, and Custom routing for the org). Why and what reaches a model: `agents/mail-desk.md` > "Code-host routes"; the job chat runs no polling loop.

## Data guard (optional)
A hook that stops an agent once when an outgoing call (a web search, a page fetch, a browser form, a network command) carries one of the owner's private values, and tells it when that value may go out; repeating the very same call goes through. A speed bump that makes the agent think again, not a wall against a determined attacker. Offer the step; skip it if they decline.
1. Ask which values count: ID and passport numbers, bank details, home address, phone, health details - their call. For each, ask when it may go out ("only for job applications", "only on the bank's own site"), or keep the default: only when they asked for it in their own message.
2. Write them to `tools/data-guard/private-data.txt`, one `<value> | <rule>` per line, the rule in their words (format and tips: `tools.md` > "Data guard"). Never commit it (git ignores it): check that `git status` does not list it.
3. Tell them it is on in Claude Code (Codex does not run it); details and how to turn it off: `tools.md` > "Data guard".

## zsh globs (optional)
Only if the owner's shell is zsh (`echo $SHELL`). Agents write unquoted globs the bash way (`grep --include=*.md`, a `?` in a URL, `[*]`), and zsh's default `nomatch` aborts the whole command with "no matches found" ("bad pattern" or "= not found" for a stray `[` or `==`). Offer to append `setopt no_nomatch no_bad_pattern no_equals` to `${ZDOTDIR:-$HOME}/.zshenv` (unless already there), so such words stay as typed, as in bash. `.zshenv` because it is the one file every zsh reads, including the non-interactive ones agents run. Check: `zsh -c setopt` and `zsh -lc setopt` both list `nobadpattern`, `noequals` and `nonomatch`. It edits a file outside this repo and changes their own terminal too, so ask first; skip it if they decline.

## Long-lived login (optional)
Only for Claude Code on the always-on machine. A `/login` login expires and must be redone, and parallel sessions refreshing it at once can revoke it, which stops every chat until someone logs in again. `claude setup-token` (needs a Claude subscription) gives a token valid for one year: the owner runs it, approves in the browser, and it prints the token. Ask before editing their user settings, which live outside this repo: put the token in `~/.claude/settings.json` under `env` as `CLAUDE_CODE_OAUTH_TOKEN`, never in this repo. Chats started after that use it; running ones keep the old login until restarted. The trade-off: the token can only call the model - no Remote Control, no claude.ai connectors, no Claude in Chrome. Put the renewal (run `claude setup-token` again, replace the value) on the owner's calendar a week before the year is up. Offer the step; skip it if they decline.
